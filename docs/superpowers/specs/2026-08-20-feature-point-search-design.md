# 特征点直线搜索设计

## 目标

将当前自动生成多条覆盖扫描线的搜索逻辑改为人工配置少量特征点。无人机每次只向现有 EGO-Planner 发布下一个特征点坐标，由规划器连续飞完整段路径，不生成中间小步航点。

目标识别、优先级调度、目标缓存、二次微调、串口投放以及投放完成后的穿越和降落流程保持不变。

## 默认路径

默认测试路径位于以起飞点为原点的 8×8 m 场地内：

```text
P1 = (-3.0, -3.0)
P2 = ( 3.0, -3.0)
P3 = ( 3.0,  0.0)
P4 = (-3.0,  0.0)
P5 = (-3.0,  3.0)
P6 = ( 3.0,  3.0)
```

无人机按照 `当前位置 → P1 → P2 → P3 → P4 → P5 → P6` 飞行。每一个特征点只发布一次给 `position_pub`，同时继续通过现有 `pos_pub` 输出当前目标；两点之间的轨迹和实时避障完全由 EGO-Planner 负责。

## 参数服务器

搜索配置改为：

```yaml
search:
  height: 1.0
  max_passes: 3
  points_x: [-3.0, 3.0, 3.0, -3.0, -3.0, 3.0]
  points_y: [-3.0, -3.0, 0.0, 0.0, 3.0, 3.0]
```

`points_x` 和 `points_y` 按相同索引组成二维特征点。任一数组为空、长度不同或包含无法转换为数值的参数时，整组路径恢复为上述六个默认点并输出 ROS 警告。搜索高度必须为正，最大搜索遍数必须大于零。

删除不再使用的搜索边界、有效扫描范围和重叠率参数：`x_min`、`x_max`、`y_min`、`y_max`、`footprint_x`、`footprint_y`、`overlap_ratio`。

## 搜索进度与中断恢复

规划器内部只保存配置的特征点、当前索引、访问状态和搜索遍数，不再计算矩形边界或扫描步距。

- 到达当前特征点后将其标记为已访问，并选择顺序中的下一个点。
- 稳定识别到高优先级目标时，保存当前索引并进入现有目标接近和投放状态。
- 投放完成后升回搜索高度，继续飞向被中断时尚未到达的特征点。
- 一遍结束且投放不足三个时，先按现有规则处理缓存的 `bridge → tent → bunker`。
- 缓存目标仍不足时反转特征点顺序，开始下一遍搜索。
- 达到 `max_passes` 后进入现有搜索结束流程。

## 代码修改范围

`CoverageSearchPlanner` 保留现有对 `MissionFSM` 使用的导航接口，包括生成、当前点、标记访问、恢复、下一遍和遍数查询；只替换其配置输入与 `generate()` 实现。这样 `MissionFSM` 的搜索状态无需大范围重写。

修改文件：

- `include/mission_node/MissionParameters.h`
- `src/MissionParameters.cpp`
- `config/mission_params.yaml`
- `include/mission_node/CoverageSearchPlanner.h`
- `src/CoverageSearchPlanner.cpp`
- `src/MissionFsm.cpp`

外部 ROS 话题、消息类型、EGO-Planner 接口和串口接口不变。

## 能力边界

少量特征点路径优先保证逻辑简单和航段连续，不构成严格的全场覆盖。能否发现全部靶标取决于实际相机有效视野和特征点布局；实测后只需调整 `points_x`、`points_y`，无需重新编译。

## 验证责任

按用户之前的要求，当前环境只进行代码结构修改，不安装依赖或执行编译、仿真、航线覆盖和实机验证。用户自行验证数组加载、航点顺序、中断恢复、反向搜索、目标识别与投放流程。
